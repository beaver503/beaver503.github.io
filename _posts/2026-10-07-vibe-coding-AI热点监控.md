## 一、需求分析

我要第一时间获取一些热点（比如 AI 大模型的更新），我不能依赖于人工手动搜索，而是利用工具自动发现指定的热点变化、或者发现最新的热点，并且及时给我发送通知。

+ 响应式兼容的 Web 页面
+ 封装成 Agent Skills 技能，能够交给其他的 AI 来监控和发现热点

**提示词设计的关键要素**

上面这段提示词虽然简短，但包含了几个重要的 AI 编程技巧：

1. 角色设定（“你是一位专业的程序员”）：明确 AI 的角色定位，让它以开发者视角思考
2. 人工确认：这是 AI 编程中非常重要的环节，防止 AI 自作主张，跑偏了方向
3. 开发顺序（先 Web 再 Skills）：明确优先级，避免 AI 同时开始多个任务
4. 技术约束（使用 OpenRouter）：指定具体的技术方案，减少 AI 的决策负担


**为什么选择 OpenRouter？**

OpenRouter 是一个 AI 模型聚合平台，它提供统一的 API 接口来调用多种大模型（DeepSeek、Claude、GPT 等）。好处是：

+ 一个 API Key 就能切换不同模型
+ 按量付费，成本可控
+ 如果某个模型不可用，可以快速切换到其他模型

测试通过，可正常使用。提交到 Git 仓库。

注意，正式开发前，我们先让AI沉淀一波文档！

这样即使AI断片儿了、或者开了最新的AI对话框，也能把已有的文档提供给AI，帮他找回记忆。

```markdown
请你把需求和方案都沉淀为 Markdown 文档，然后再进行开发，注意，你必须利用 MCP 获取到最新的 API 对接和技术实现方法，防止使用过时的代码

```

**文档沉淀的重要性**

在 AI 编程中，**文档沉淀**是一个容易被忽视但极其重要的环节。原因如下：

1. AI 的上下文窗口有限：每个对话能记住的内容是有限的，文档可以作为持久化的“记忆”
2. 方便新对话恢复记忆：当你需要开新的 AI 对话时，只需提供文档即可让 AI 快速了解项目背景
3. 团队协作基础：如果有其他人加入项目，文档是最好的入门材料
4. 版本追溯：方案的演进过程可以通过文档记录下来

建议至少沉淀以下文档：

+ 需求文档：明确要做什么
+ 方案设计文档：明确怎么做
+ 技术选型说明：记录为什么选择某项技术

💡 这些文档不需要非常正式，Markdown 格式即可，关键是内容完整、便于 AI 理解。

## 三、前端页面优化


**“AI味儿”是什么？**

你可能注意到，很多 AI 生成的网页都有类似的特征：蓝紫色渐变背景、圆角卡片、通用图标。这就是所谓的 AI 味儿

为什么会这样？因为大模型在训练时看到了大量类似风格的设计，形成了一种“默认审美”。

要消除 AI 味儿，核心思路是 **给 AI 更明确的设计约束**：

1. 指定色彩方案：不要让 AI 自由发挥，明确告诉它用什么颜色
2. 使用特定 UI 库：比如 Aceternity UI，它有独特的视觉风格
3. 注入情感和场景：告诉 AI 你的产品是什么调性（科技感、极客风等）
4. 使用前端美化技能：让 AI 参考专业的 UI/UX 设计规范

```markdown
目前的界面风格过于大众化，请你在保持功能易用的前提下，帮我优化前端页面。

你需要利用前端美化技能（ui ux pro max）进行设计开发，并且必须采用 Aceternity UI 组件库（通过 Context7 插件来获取最新用法），来增强网站的科技感，但是注意不要过于花里胡哨、影响了页面的正常加载或使用。

我自己是一位程序员，追求简洁高效、直观、充满科技感的页面，我急切地想要发现热点，想要第一时间看到有价值的内容，你需要感受我的情绪，让前端页面体现出来。
```

这段提示词有几个值得学习的技巧：

1. 指出问题（“过于死板”）：让 AI 明确知道当前状态不满意
2. 保持底线（“保持功能易用”）：强调不能为了好看牺牲可用性
3. 指定工具（Skills + Aceternity UI + Context7）：明确告诉 AI 用什么来实现
4. 注入情感（“感受我的情绪”）：这是一个高级技巧，通过情感描述让 AI 理解产品调性

特别要注意第4点 —— 告诉 AI 用户是谁、追求什么感觉，比直接描述颜色和布局更有效。AI 会根据 “AI 编程博主”、“科技感”、“急切地想要发现热点”这些描述，自主决定配色、动效和布局方案


**处理 AI 中断的方法**

在 AI 编程中，遇到中断是很常见的，原因可能包括：

1. 网络不稳定：连接 AI 服务的网络波动
2. 上下文过长：对话历史太多，超出了模型的上下文窗口
3. 任务过大：一次性要改的代码太多

分享一些应对策略：

| 方案 | 说明 | 适用场景 |
| --- | --- | --- |
| 拆分任务 | 把大任务拆成多个小任务，分步完成 | 改动范围大（如全站 UI 重构） |
| 换模型 | 切换到更稳定的大模型 | 特定模型频繁断连 |
| 新开对话 | 重新开一个对话窗口 | 上下文过长导致的中断 |
| 提供记忆 | 通过提示词帮 AI 找回之前的工作记忆 | 新对话中继续之前的任务 |

如果 AI 执行还是中断，可以尝试新开一个 AI 对话，并且通过提示词帮 AI 找回记忆：

## 五、信息流筛选和排序

**为什么需要筛选和排序？**  
当系统从8+个信息源采集数据后，一次扫描可能产生几十甚至上百条结果。如果所有内容平铺展示，用户需要  
逐条阅读才能找到有价值的信息，效率很低。  
筛选和排序解决了两个核心问题：  
1,信息过载：通过筛选条件缩小范围，快速找到特定类型的信息  
2.优先级判断：通过排序将最有价值的信息排在最前面  
这在信息系统设计中是一个经典需求，类似于电商网站的商品筛选，新闻客户端的内容排序。

## 六、优化热点信息展示


**目前的问题**  
目前已经展示了重要性，来源，关键词，帖子的标题，帖子的描述（需要确认是原始描述还是a生成的）,相关  
性，热度（点赞数）等等，但是可能还需要人工跳转到原始网站去获取一些数据（比如帖子的发布时间）,浪费了  
些时间。所以目标是能够节省人工判断信息价值的时间，更快地定位需要的热点信息。  
信息展示的设计原则  
好的信息展示应该遵循"一眼值不值"原则，用户只需要看一眼，就能判断这条信息是否值得深入阅读。  
要实现这一点，需要在有限的展示空间内提供关键决策信息：  
决策维度 对应信息 为什么重要  
时效性 发布时间，抓取时间 判断信息是否过时  
热度 点赞，转发，浏览量 判断信息的关注度  
可信度 作者信息，认证状态 判断信息来源是否可信  
相关性 AI 相关性评分和理由 判断信息是否与关注话题相关  
原文链接 一键跳转 方便深入阅读原始内容  
前我们的界面缺少部分关键信息（如发布时间，互动数据等）,导致用户需要额外跳转才能获取完整信息。

## 七、优化 AI 分析准确度 + 扩展思路


**问题根因分析**  
AI 相关性分析不准确的原因可能有多个层面：  
1,搜索层面：搜索引擎返回的内容本身就不够相关（关键词过于宽泛或模糊）  
2,prompt层面：给a的分析提示词不够精确，没有明确要求判断"是否直接提到关键词"  
3.闻值层面：相关性评分的闻值设置不合理，低相关性的内容也被保留  
4.评估层面：缺乏系统化的测试机制，无法量化分析质量  
要解决这个问题，需要从多个层面同时优化。

```markdown
你是一位专业的程序员，现在请你根据我的需求和方案、以及已经开发完成的前端和后端项目，在此基础上进行优化和功能扩展。

@方案设计文档
必须完整分析前端和后端已有代码
```

skill-creator会帮助 AI 遵循标准的 skills 开发规范，确保生成的技能格式正确，结构完整，兼容多种 AI 编程工  
具。

需要考虑几个关键问题：  
1.独立性：skils是否需要依赖我们开发的后端服务？  
2.易用性：用户安装后是否开箱即用？  
3.兼容性：是否能在多种 AI 编程工具中使用？  
4.安全性：是否需要用户提供apikey?  
理想的Skills应该是完全自包含的一安装后不需要额外启动服务，不需要配置数据库，不需要必须的 api key

| 对比维度 | 旧方案（依赖 Server） | 新方案（完全自包含） |
| --- | --- | --- |
| 安装难度 | 需要启动后端服务 | 复制文件夹即可 |
| 依赖项 | Node.js + 数据库 + OpenRouter | 仅需 Python（可选） |
| AI 分析 | 通过 OpenRouter API 调用 | AI 编程工具自身完成分析 |
| 搜索能力 | 调用后端 API | 内置 Python 搜索脚本 |
| 可移植性 | 只能在有服务器的环境使用 | 任何地方都能用 |

新方案的核心创新点是 Claude 即 AI 引擎，不需要额外调用 OpenRouter，而是让 AI 编程工具自身（比如 Claude、Copilot 中的模型）来完成内容分析。这样做的好处：

1. 不需要用户额外配置 API Key
2. 不产生额外的 AI 调用费用
3. 分析质量取决于用户使用的 AI 模型
